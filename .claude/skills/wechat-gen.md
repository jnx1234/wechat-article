# 微信公众号减脂文章生成器

## 触发命令
```
/wechat-gen
```
可选：`/wechat-gen --topic "平台期突破"` 指定主题方向

## 概述

通过 6 步自动化流水线，每天生成 **1 篇**可发布的减脂类公众号文章：

```
🎯 标题生成器 (20个爆款标题，含反转型)
  ↓
⭐ 标题甄选器 (精选1个最佳)
  ↓
📝 正文生成器 (1500-2500字，8段结构，含配图位)
  ↓
👤 人设润色器 (统一"小轻"口吻)
  ↓
💕 情绪增强器 (增加真实感)
  ↓
📐 排版优化器 (短句留白分段)
  ↓
🧹 AI去味器 (口语化 + 术语错别字检查)
  ↓
📎 拼接固定文案 (引导块/免责声明/结尾转化块)
  ↓
📁 归档保存 (output/YYYY-MM-DD/)
```

## 执行流程

### Step 0: 加载配置
1. 读取 `config/persona.md` — 获取当前账号人设与固定文案
2. 确定今日主题（用户输入，或按下方「主题策略」从 `config/topics.md` 选）
3. 确定今日日期 `YYYY-MM-DD`

### Step 1: 调用 Workflow 脚本
```javascript
Workflow({
  scriptPath: "C:\\Users\\11200\\Desktop\\team\\scripts\\wechat-gen-workflow.js",
  args: { topic: "<今日主题>" }
})
```

### Step 2: 处理返回结果
返回字段：
- `allTitles`: 20 个标题的完整列表（含类型和评分）
- `selected`: 精选的 1 个标题（含入选理由）
- `articles`: 1 篇成稿的数组，每项含：
  - `title` — 完整标题（含成果后缀）
  - `body` — **完整成稿**（已拼好引导块、免责声明、结尾转化块）
  - `content` — 纯正文（不含固定文案，需要改内容时用这个）
  - `wordCount` — **成稿总字数**（含引导块/免责声明/结尾块，已剔除配图占位符和空白），对应 1500-2500 的口径
  - `imageSlots` — 配图位数量

### Step 3: 保存文件
在 `output/YYYY-MM-DD/` 目录下创建：

#### 文章文件: `article-01-<标题缩写>.md`
```yaml
---
title: "文章标题（138-106已掉32斤）"
date: YYYY-MM-DD
word_count: 2180
image_slots: 22
type: "反转型"
selection_reason: "标题点击吸引力强，适合展开干货内容"
weight_tag: "（138-106已掉32斤）"
---
```
正文直接使用 `articles[0].body`（完整成稿，可直接复制到公众号后台）。

#### 每日摘要文件: `_summary.md`
```markdown
# 📋 减脂文章生成日报 — YYYY-MM-DD
## 主题方向：<topic>
## 生成时间：<timestamp>
## 标题总览（20个）
| # | 类型 | 标题 | 评分 | 入选 |
|---|------|------|------|------|
| 1 | 反转型 | xxx | 95 | ⭐ |
...

## 今日文章
### 🥇 《标题》
- **入选理由**：...
- **字数**：2,180（成稿总字数，含固定文案块）
- **配图位**：12 个（见正文中【配图：...】占位符）
- **标签**：...

## 统计
- 标题总数：20
- 成稿：1 篇
- 成稿总字数：约 2,180

```

### Step 4: 输出报告
向用户展示：
- 📊 今日生成摘要
- 🖼️ 待配图清单（把所有 `【配图：xxx】` 描述提取成列表，方便一次性找图）
- 📱 待办：引导块里有一句"点上面的链接就能直接用"，发之前在这一句**上方**插入真正的小程序链接（小程序名：轻食小本）
- 📁 文件保存位置

## 主题策略
用户未指定 `--topic` 时，读 `config/topics.md`，从中选 **1 个大类 + 1 个具体选题**，
把具体选题原样作为 `args.topic` 传进工作流脚本。

- 8 个大类各有分工（吸粉 / 专业度 / 信任 / 流量），注意轮换，别连续多天发同一类
- 「单一食物」类不穷举，按 `config/topics.md` 文末的展开模板现造选题
- 「热点/争议型」只做原理解读，不推荐任何具体品牌或产品

## 注意事项
- 固定数字 **138→106、32斤** 全文必须一致，不许出现第二种说法
- 固定文案块（引导块/免责声明/结尾转化块）由脚本拼接，**不要让 agent 改写**
- 小程序只在**开头引导块**提这一次（一句话带过，2026-09-20 起不再用卡片占位符），正文里**不写名字、不写怎么搜**
- 成果播报只写三件事：体重数字 → 落到"看得见才没放弃" → 否定式排比。**不再重讲小程序的来龙去脉**
- 文章结构 8 段（成果播报 / 共鸣痛点 / 生活场景 / 到底凭啥 / 主清单 / 能抄作业的方案 / 附加小节≤2 / 真心话），
  详见 `config/persona.md` 的「文章结构」。其中**生活场景段必写**、**凭啥段至少 2-3 个角度且必须给数字**
- 「同一件事全文只讲一次」：凭啥段讲过的原理，附加小节别再讲；主清单管"怎么吃"，抄作业方案管"什么时候吃多少"
- 清单每一项必须写全 5 拍，尤其第 ⑤ 拍"替代方案"不能省
- 标题正文都禁止绝对化用语：唯一/最快/必须/彻底/根治/巨
- 反转型是可选能力，不是每篇都用，按选题决定
- **全文不许出现 `**` 加粗符号**（公众号纯文本粘贴会原样露出星号），脚本里有兜底会强行删掉
- 输出文件使用 UTF-8 编码
- 任一步 agent 返回 null 时沿用上一步结果，不中断流水线

## 已经踩过的坑（脚本里修好了，改脚本时别改回去）

1. **字数会超**。成稿 = agent 正文 + 标题行 + 引导块 + 免责声明 + 结尾块，后四块约 254 字。所以 agent 的写作目标是 `1500-2500` **减去这 254 字**，脚本用 `BODY_MIN` / `BODY_MAX` 动态算好注进 prompt。直接跟 agent 说"写 1500-2500 字"必然超。

2. **真心话小标题会被改写**。它在第 1 阶段就修正过了，但后面 4 个 agent（人设/情绪/排版/去味）会把它改回「跟大家说点真心话」这类说法。所以第 1 阶段改完立刻换回 `【固定小标题】` 标记，靠 HANDOFF 一路保护到 `assemble()` 才还原。

3. **配图位会背靠背**。agent 会在相邻两段之间连着放两个 `【配图：...】`，公众号里就是上下贴两张图。prompt 里已禁止，交付前也要扫一遍。

4. **配图位会写太多**。数量在脚本顶部的 `IMG_MIN` / `IMG_MAX` 两个常量里定（现值 10-14），prompt 从常量取，**不要写死数字**。agent 有"多放点更保险"的倾向，超上限的要在交付前删掉。

5. **结构名会漏进正文**。内部结构名（成果播报/共鸣痛点/生活场景/到底凭啥/主清单/能抄作业的方案/附加小节/真心话）
   是给小轻自己看的分段记号，**不许当小标题出现在文章里**。prompt 里写了，`assemble()` 里还有 `stripStructLabels()` 兜底，
   改脚本时两处都要留着。
